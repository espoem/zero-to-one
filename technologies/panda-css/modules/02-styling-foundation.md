# Module 02: Styling Foundation

Mastering Panda CSS begins with understanding how styles are declared, scoped, merged, and executed. This module walks through configuring Panda CSS in a production repository, authoring atomic styles with `css()`, designing responsive user interfaces with mobile-first breakpoints, working with advanced pseudo-selectors and conditions, and deterministically merging style objects. It concludes with an interactive hands-on exercise and a complete production-grade solution.

## Lesson 2.1: Installing & Configuring Panda CSS

Setting up Panda CSS establishes the bridge between your source files and the static CSS extraction engine. Unlike runtime libraries that only need an npm install, Panda CSS integrates into your build system via PostCSS and generates a typed local package (`styled-system`).

### 1. Installation and Project Initialization

In your project root (whether Vite, Next.js, or Remix), install `@pandacss/dev` as a development dependency and run the initialization CLI:

```bash
npm install -D @pandacss/dev
npx panda init --postcss
```

This command creates two key files: `panda.config.ts` and `postcss.config.cjs`.

### 2. Configuration (`panda.config.ts`)

The `panda.config.ts` file controls file discovery, output location, preflight resets, JSX generation, and theme contracts:

```ts
// panda.config.ts
import { defineConfig } from '@pandacss/dev';

export default defineConfig({
  // Enable modern CSS reset
  preflight: true,

  // JSX factory generation: set to 'react', 'solid', or 'vue' if JSX patterns are desired
  jsxFramework: 'react',

  // Where to look for CSS declarations
  include: ['./src/**/*.{js,jsx,ts,tsx}', './pages/**/*.{js,jsx,ts,tsx}', './app/**/*.{js,jsx,ts,tsx}'],

  // Files to exclude from AST scanning
  exclude: ['node_modules', 'dist', '.next', 'styled-system'],

  // The output directory for the generated styled-system package
  outdir: 'styled-system',

  // Strict token enforcement: throws build errors when arbitrary values are used
  strictTokens: false,

  // Theme definition
  theme: {
    extend: {
      tokens: {
        colors: {
          brand: {
            50: { value: '#eef2ff' },
            500: { value: '#6366f1' },
            600: { value: '#4f46e5' },
            700: { value: '#4338ca' },
          },
        },
      },
    },
  },
});
```

### 3. PostCSS Integration (`postcss.config.cjs`)

Ensure your PostCSS configuration registers `@pandacss/postcss`:

```js
// postcss.config.cjs
module.exports = {
  plugins: {
    '@pandacss/postcss': {},
  },
};
```

### 4. Cascade Layers in Your Main Stylesheet

In your application's entry CSS file (e.g., `src/index.css` or `app/globals.css`), import the standard cascade layers. This directive tells the browser the priority order for resets, tokens, recipes, and atomic utilities:

```css
/* src/index.css */
@layer reset, base, tokens, recipes, utilities;
```

### 5. Automation: `panda codegen` in `prepare`

Because `styled-system` is generated code, you should add it to `.gitignore` to avoid checking thousands of autogenerated TypeScript definition lines into version control. To ensure `styled-system` exists immediately after `npm install` (especially in CI/CD pipelines or when other developers clone the repository), add `panda codegen` to your `package.json` `prepare` script:

```json
{
  "scripts": {
    "prepare": "panda codegen",
    "dev": "vite",
    "build": "panda codegen && vite build"
  }
}
```

```gitignore
# .gitignore
node_modules
dist
.next
styled-system
```

### ❌ Anti-Pattern vs ✅ Best Practice

#### ❌ Anti-Pattern: Committing `styled-system` to Version Control
Committing the generated `styled-system` folder leads to massive git diffs on every minor Panda version bump or token change, causing merge conflicts across feature branches.

#### ✅ Best Practice: Ignored `styled-system` with `prepare` Codegen Hook
Add `styled-system` to `.gitignore` and run `panda codegen` inside `prepare` and `build` scripts in `package.json`. This guarantees clean git histories and ensures CI/CD environments always compile with freshly generated token definitions.

## Lesson 2.2: Styling Basics (`css()`)

The `css()` function from `styled-system/css` is the primary styling primitive. It accepts a style object containing standard CSS properties, ergonomic shorthands, design tokens, and condition blocks, returning atomic class names.

### Shorthand Properties Mapping

Panda CSS provides shorthand properties that map directly to standard CSS rules. Shorthands reduce boilerplate without sacrificing readability:

| Shorthand | Target CSS Property | Example Usage |
| :--- | :--- | :--- |
| `bg` | `background-color` / `background` | `bg: 'brand.500'` |
| `p`, `px`, `py` | `padding`, `padding-inline`, `padding-block` | `px: '4', py: '2'` |
| `pt`, `pr`, `pb`, `pl` | `padding-top`, `padding-right`, `padding-bottom`, `padding-left` | `pt: '6'` |
| `m`, `mx`, `my` | `margin`, `margin-inline`, `margin-block` | `mx: 'auto', my: '4'` |
| `w`, `h` | `width`, `height` | `w: 'full', h: '12'` |
| `minW`, `maxW` | `min-width`, `max-width` | `maxW: '2xl'` |
| `minH`, `maxH` | `min-height`, `max-height` | `minH: '100vh'` |
| `rounded` | `border-radius` | `rounded: 'md'` |
| `roundedTop`, `roundedBottom` | `border-top-left/right-radius`, etc. | `roundedTop: 'lg'` |
| `shadow` | `box-shadow` | `shadow: 'md'` |
| `lineClamp` | Multi-line text truncation | `lineClamp: 2` |
| `truncate` | Single-line overflow ellipsis | `truncate: true` |

### Pseudo-Classes and State Selectors

Pseudo-classes in Panda CSS begin with an underscore (`_`). This naming convention prevents naming collisions with standard CSS properties and makes interactive states immediately identifiable:

```tsx
import { css } from 'styled-system/css';

export function ActionButton() {
  return (
    <button
      className={css({
        bg: 'brand.600',
        color: 'white',
        px: '5',
        py: '2.5',
        rounded: 'lg',
        fontWeight: 'semibold',
        transition: 'all 0.2s ease',
        cursor: 'pointer',

        // Hover state
        _hover: {
          bg: 'brand.700',
          shadow: 'md',
        },

        // Accessible keyboard focus state
        _focusVisible: {
          outline: '2px solid',
          outlineColor: 'brand.500',
          outlineOffset: '2px',
        },

        // Active / Pressed state
        _active: {
          transform: 'scale(0.98)',
        },

        // Disabled state
        _disabled: {
          opacity: 0.5,
          cursor: 'not-allowed',
          _hover: {
            bg: 'brand.600',
            shadow: 'none',
          },
        },

        // Pseudo elements
        _before: {
          content: '""',
          display: 'inline-block',
          w: '2',
          h: '2',
          rounded: 'full',
          bg: 'emerald.400',
          mr: '2',
        },
      })}
    >
      Live System Status
    </button>
  );
}
```

### Strict Type Safety

Panda CSS generates strict TypeScript definitions for all styles. If you make a typo in a property name or supply an invalid token name, TypeScript produces a compiler error before the code runs:

```tsx
css({
  // ❌ Type Error: Type '"17px"' is not assignable to type 'SpacingToken | ...'
  p: '17px',

  // ❌ Type Error: Object literal may only specify known properties, and 'backgroud' does not exist.
  backgroud: 'red',
});
```

### ❌ Anti-Pattern vs ✅ Best Practice

#### ❌ Anti-Pattern: Unstyled Focus Outlines or Relying on `_focus`
```tsx
// ❌ Disabling outline or using generic _focus instead of _focusVisible
css({
  outline: 'none', // Destroys accessibility for keyboard users!
  _focus: { bg: 'blue.100' }, // Fires on mouse clicks, causing ugly click rings
})
```
*Why this fails:* Disabling outlines isolates keyboard navigators, violating WCAG standards. Using `_focus` applies focus rings during mouse clicks, leading developers to turn outlines off completely.

#### ✅ Best Practice: Accessible `_focusVisible` Styling
```tsx
// ✅ Crisp, accessible focus indicators that only appear during keyboard navigation
css({
  _focusVisible: {
    outline: '2px solid',
    outlineColor: 'brand.600',
    outlineOffset: '2px',
  },
})
```
*Why this succeeds:* `_focusVisible` triggers only when navigating via keyboard (or assistive tech), leaving mouse clicks clean while providing visible indicators for accessibility audits.

## Lesson 2.3: Responsive Design

Responsive styling in Panda CSS follows a mobile-first paradigm. Styles declared at the root level apply to all screen widths, while breakpoint modifiers override styles for larger screens.

### The Breakpoint System

Panda CSS includes industry-standard mobile-first breakpoints out of the box:

- **`base`**: `0px` (Default mobile view)
- **`sm`**: `640px`
- **`md`**: `768px`
- **`lg`**: `1024px`
- **`xl`**: `1280px`
- **`2xl`**: `1536px`

### Object Syntax vs Array Syntax

Panda supports two responsive syntaxes: Object Syntax and Array Syntax.

```tsx
// 1. Array Syntax (Positional order: [base, sm, md, lg, xl])
const arrayStyle = css({
  flexDirection: ['column', 'column', 'row'],
});

// 2. Object Syntax (Explicit named keys)
const objectStyle = css({
  flexDirection: { base: 'column', md: 'row' },
});
```

#### Why Object Syntax Is Strongly Preferred
While array syntax is shorter, it is fragile in production. If you want to modify a property only on `lg` screens, array syntax forces you to supply redundant placeholders: `['column', 'column', 'column', 'row']`. If a team member modifies default breakpoints or skips a slot, the entire responsive cascade shifts invisibly. Object syntax is explicit, self-documenting, and allows sparse overrides (`{ base: 'column', lg: 'row' }`).

### Breakpoint Ranges and Targeted Queries

Panda CSS provides built-in condition helpers that target specific screen intervals:

- **`smDown`**: `@media (max-width: 639px)` — Targets only mobile devices below `sm`.
- **`mdDown`**: `@media (max-width: 767px)` — Targets phones and small tablets.
- **`mdToLg`**: `@media (min-width: 768px) and (max-width: 1023px)` — Targets tablet screens exclusively.
- **`lgOnly`**: Targets only the `lg` breakpoint interval.

```tsx
const sidebarStyle = css({
  display: 'block',
  w: '64',
  // Visible on desktop, completely hidden on mobile below md
  display: { smDown: 'none', md: 'block' },
});
```

### The `hideFrom` and `hideBelow` Utilities

For responsive DOM visibility, Panda CSS provides `hideFrom` and `hideBelow` utility properties. These properties apply `display: none` at designated breakpoints:

```tsx
import { css } from 'styled-system/css';

export function Navigation() {
  return (
    <nav className={css({ display: 'flex', alignItems: 'center', p: '4' })}>
      <div className={css({ fontWeight: 'bold' })}>Acme Corp</div>
      
      {/* Desktop links: hidden on screens below md */}
      <div className={css({ hideBelow: 'md', display: 'flex', gap: '4', ml: '8' })}>
        <a href="#features">Features</a>
        <a href="#pricing">Pricing</a>
      </div>

      {/* Mobile hamburger menu button: hidden on screens from md upwards */}
      <button className={css({ hideFrom: 'md', ml: 'auto', p: '2' })} aria-label="Open Menu">
        ☰
      </button>
    </nav>
  );
}
```

### ❌ Anti-Pattern vs ✅ Best Practice

#### ❌ Anti-Pattern: Sparse Array Syntax
```tsx
// ❌ Fragile array syntax with repeated entries
css({
  padding: ['1rem', '1rem', '1rem', '2.5rem'],
})
```
*Why this fails:* Reading `padding[3]` requires manually counting breakpoints in your head. Changing a middle breakpoint breaks the index mapping across the entire codebase.

#### ✅ Best Practice: Declarative Object Syntax
```tsx
// ✅ Explicit, clear, and sparse object syntax
css({
  p: { base: '4', lg: '10' },
})
```
*Why this succeeds:* The declaration states exactly what happens: 1rem padding by default, scaling to 2.5rem at the `lg` breakpoint. Everything in between inherits the base value without filler.

## Lesson 2.4: Nested Styles & Conditions

Modern user interfaces require coordinating styles across parents, children, siblings, and component state attributes. Panda CSS provides structured nesting, group modifiers, peer selectors, and custom conditions.

### Nesting with the `&` Selector

Use `&` to reference the current selector. This allows targeting nested elements, direct children, or sibling elements:

```tsx
const articleStyle = css({
  p: '6',
  // Target direct children paragraphs
  '& > p': {
    color: 'gray.700',
    lineHeight: 'relaxed',
  },
  // Target child icons on hover
  '&:hover svg': {
    transform: 'translateX(4px)',
    color: 'brand.600',
  },
  // Adjacent sibling selector
  '& + &': {
    borderTopWidth: '1px',
    borderTopColor: 'gray.200',
  },
});
```

### Group and Peer Modifiers

When hovering or focusing a parent container needs to style child elements, use the `group` modifier. When a sibling input needs to control adjacent sibling styles, use the `peer` modifier.

#### Group Modifiers (`group` and `_groupHover`)
Assign `className="group"` to the parent container, then use `_groupHover` or `_groupFocus` on any child element:

```tsx
import { css } from 'styled-system/css';

export function FeatureCard() {
  return (
    <div
      className={`group ${css({
        p: '6',
        bg: 'white',
        rounded: 'xl',
        borderWidth: '1px',
        borderColor: 'gray.200',
        cursor: 'pointer',
        transition: 'border-color 0.2s',
        _hover: { borderColor: 'brand.500', shadow: 'md' },
      })}`}
    >
      <div
        className={css({
          w: '10',
          h: '10',
          rounded: 'lg',
          bg: 'brand.50',
          color: 'brand.600',
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
          transition: 'all 0.2s',
          // Elevates and changes color when the parent card is hovered!
          _groupHover: {
            bg: 'brand.600',
            color: 'white',
            transform: 'scale(1.1)',
          },
        })}
      >
        ★
      </div>
      <h4 className={css({ mt: '4', fontWeight: 'bold' })}>Cloud Infrastructure</h4>
    </div>
  );
}
```

#### Peer Modifiers (`peer` and `_peerChecked`)
Assign `className="peer"` to a control (like an input), and use `_peerChecked`, `_peerInvalid`, or `_peerFocus` on adjacent siblings:

```tsx
export function CustomCheckbox({ label }: { label: string }) {
  return (
    <label className={css({ display: 'inline-flex', alignItems: 'center', gap: '3', cursor: 'pointer' })}>
      <input type="checkbox" className={`peer ${css({ srOnly: true })}`} />
      <div
        className={css({
          w: '5',
          h: '5',
          rounded: 'md',
          borderWidth: '2px',
          borderColor: 'gray.300',
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
          transition: 'all 0.15s ease',
          // Styles react when the sibling peer input is checked
          _peerChecked: {
            bg: 'brand.600',
            borderColor: 'brand.600',
            color: 'white',
          },
          _peerFocus: {
            ring: '2px',
            ringColor: 'brand.400',
          },
        })}
      >
        ✓
      </div>
      <span className={css({ fontSize: 'sm', color: 'gray.700' })}>{label}</span>
    </label>
  );
}
```

### Data-Attribute Conditions

Modern component libraries (Ark UI, Radix UI) use `data-*` attributes to signal UI states (`data-state="open"`, `data-disabled`, `data-loading`). Panda CSS provides built-in condition shortcuts:

- `_expanded`: Targets `&[aria-expanded="true"]` or `&[data-expanded]`
- `_selected`: Targets `&[aria-selected="true"]` or `&[data-selected]`
- `_loading`: Targets `&[data-loading]`
- `_open`: Targets `&[data-state="open"]` or `&[open]`

### Defining Custom Conditions in `panda.config.ts`

You can extend Panda's condition dictionary with your own domain-specific CSS selectors via `conditions.extend`:

```ts
// panda.config.ts
import { defineConfig } from '@pandacss/dev';

export default defineConfig({
  conditions: {
    extend: {
      isScrolled: '&[data-scrolled="true"]',
      highContrast: '@media (prefers-contrast: more)',
      supportsBackdrop: '@supports (backdrop-filter: blur(10px))',
    },
  },
});
```

Once defined and generated, these conditions are strictly typed and available as `_isScrolled`, `_highContrast`, and `_supportsBackdrop` inside `css()` calls.

### ❌ Anti-Pattern vs ✅ Best Practice

#### ❌ Anti-Pattern: Manual State Classes in JavaScript
```tsx
// ❌ Manually toggling utility class strings via boolean flags
<div className={`icon ${isParentHovered ? 'bg-brand-600 text-white' : 'bg-gray-100'}`} />
```
*Why this fails:* Requires binding React mouse event handlers (`onMouseEnter`, `onMouseLeave`), causing re-renders across the component tree just to apply a visual hover style.

#### ✅ Best Practice: CSS Group Modifiers
```tsx
// ✅ Pure CSS group hover without JavaScript state or re-renders
<div className="group">
  <div className={css({ bg: 'gray.100', _groupHover: { bg: 'brand.600', color: 'white' } })} />
</div>
```
*Why this succeeds:* The state change executes natively in the browser's CSS engine with zero JavaScript event listeners and zero React re-renders.

## Lesson 2.5: Merging Styles Deterministically (`css.raw()` & `cx()`)

A recurring challenge in atomic CSS is handling style overrides. When building reusable design system components, parent components frequently need to pass custom style overrides to child components.

### Why String Concatenation Fails

Consider what happens if you attempt to merge atomic styles using naive string concatenation:

```tsx
const baseClass = css({ bg: 'red.500', p: '4' });
// Generated: "bg_red.500 p_4"

const overrideClass = css({ bg: 'blue.500' });
// Generated: "bg_blue.500"

// String concatenation:
const finalClass = `${baseClass} ${overrideClass}`;
// Output: "bg_red.500 p_4 bg_blue.500"
```

In standard CSS, when an HTML element has both `class="bg_red.500 bg_blue.500"`, the element's background color is determined by which class appears later in the generated CSS stylesheet—**not** which class appears later in the HTML `class` attribute. If `bg_red.500` happens to be defined later in the CSS file than `bg_blue.500`, the red background wins, silently ignoring your override!

### Resolving Overrides Deterministically: `css.raw()` and `css()`

Panda solves this cleanly: `css()` accepts multiple style objects and merges them deterministically at the JavaScript object level **before** resolving atomic class names:

```tsx
import { css } from 'styled-system/css';

const baseStyle = { bg: 'red.500', p: '4' };
const overrideStyle = { bg: 'blue.500' };

// Merged deterministically: { bg: 'blue.500', p: '4' }
const className = css(baseStyle, overrideStyle);
// Generated: "bg_blue.500 p_4" (Only one background class is ever generated!)
```

`css.raw()` is a helper function that returns the uncompiled raw style object while preserving full TypeScript type safety and autocompletion:

```tsx
import { css } from 'styled-system/css';

const buttonBase = css.raw({
  display: 'inline-flex',
  px: '4',
  py: '2',
  bg: 'brand.500',
  color: 'white',
});
```

### When to Use `cx()` vs `css()`

- **Use `cx(...)`**: When combining independent atomic classes that do not conflict (e.g., combining a recipe class name with an external utility class or external class name). `cx` performs fast falsy filtering and string joining.
- **Use `css(styleA, styleB)`**: When combining style objects where properties may overlap and you need the latter style to reliably override the former.

### Component `css` Prop Forwarding Pattern

In a production component library, declare a `css?: SystemStyleObject` prop to allow consumers to supply deterministic overrides:

```tsx
import { css } from 'styled-system/css';
import type { SystemStyleObject } from 'styled-system/types';

interface CardProps {
  children: React.ReactNode;
  css?: SystemStyleObject;
}

const defaultCardStyles = css.raw({
  p: '6',
  rounded: 'xl',
  bg: 'white',
  borderWidth: '1px',
  borderColor: 'gray.200',
  shadow: 'sm',
});

export function Card({ children, css: overrideCss }: CardProps) {
  // Deterministic merge: overrideCss overwrites defaultCardStyles at the object level
  const resolvedClass = css(defaultCardStyles, overrideCss);

  return <div className={resolvedClass}>{children}</div>;
}
```

### ❌ Anti-Pattern vs ✅ Best Practice

#### ❌ Anti-Pattern: Concatenating Atomic Class Strings
```tsx
// ❌ Merging generated class strings leads to stylesheet order race conditions
function Box({ className }: { className?: string }) {
  const base = css({ bg: 'white', p: '4' });
  return <div className={`${base} ${className}`} />;
}
```
*Why this fails:* If `className` contains a different background, the browser applies whichever rule appears later in the generated CSS bundle. Overrides fail intermittently based on build chunking.

#### ✅ Best Practice: Object Merging with `css.raw()` and `css()`
```tsx
// ✅ Object-level merging guarantees the override always wins
import { css } from 'styled-system/css';
import type { SystemStyleObject } from 'styled-system/types';

function Box({ css: overrideStyles }: { css?: SystemStyleObject }) {
  const base = css.raw({ bg: 'white', p: '4' });
  return <div className={css(base, overrideStyles)} />;
}
```
*Why this succeeds:* Conflicting properties are resolved during object composition before CSS class assignment. Only the winning property class is emitted.

## Lesson 2.7: Solution — Step-by-Step Implementation

Here is the complete, production-grade implementation of the SaaS Pricing & Profile Card component.

```tsx
// src/components/PricingCard.tsx
import { useState } from 'react';

import type { SystemStyleObject } from 'styled-system/types';

export interface PricingCardProps {

  annualPrice: number;
  features: string[];

  onSelectPlan?: (isAnnual: boolean) => void;

  bg: 'white',

    borderColor: 'brand.500',

  const [isAnnual, setIsAnnual] = useState(false);

  const cardClassName = css(baseCardStyles, overrideCss);

  return (

      {/* Header section */}
      <div>
        <div className={css({ display: 'flex', alignItems: 'center', justifyContent: 'space-between' })}>
```

### Architectural Breakdown of the Solution
1. **Deterministic Merging**: `baseCardStyles` is declared with `css.raw(...)` and merged via `css(baseCardStyles, overrideCss)`. Any custom background, padding, or border radius supplied by parent callers cleanly replaces default properties at the object level.
2. **Accessible Peer Switch**: The native checkbox is hidden visually with `srOnly: true` while remaining reachable via tab navigation. The switch background styles react via `_peerChecked` and keyboard rings via `_peerFocus`.
3. **Compound Interactive Feedback**: Adding `className="group"` to the parent container enables the checkmark indicators to animate forward and shift colors via `_groupHover` whenever the user hovers anywhere over the card.
4. **Data-Attribute Loading State**: The CTA button uses `data-loading={isLoading ? '' : undefined}`. This triggers the `_loading` condition, dimming opacity and preventing double-submits cleanly without complex conditional class logic.
