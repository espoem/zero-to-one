# Glossary: Containers and OCI Runtimes

This glossary defines core terminology for Linux kernel primitives, OCI specifications, container runtimes, and supply-chain security, including required root glossary terms reused verbatim.

| English Term | Czech Term | Definition & Context | Primary Reference |
| :-- | :-- | :-- | :-- |
| **Idempotence / Idempotency** | **Idempotence** | The property of an operation where multiple identical executions yield the exact same system state as a single execution (`f(f(x)) = f(x)`). | ISO/IEC 2382, RFC 9110 (HTTP Semantics) |
| **Graceful Shutdown** | **Řádné ukončení služby (graceful shutdown)** | The coordinated termination procedure of stopping new traffic ingestion, draining in-flight requests within a bounded deadline, and releasing persistent connections. | Cloud-Native Operations Standards |
| **Load Shedding** | **Shazování zátěže (load shedding)** | An overload defense mechanism that proactively rejects excess incoming requests when queue depth, event-loop delay, or resource utilization crosses a critical threshold. | Beyer et al. (Site Reliability Engineering) |
| **Circuit Breaker** | **Jistič (circuit breaker)** | A fault-isolation pattern or memory safeguard that trips to fail fast when an upstream dependency degrades or when a node's memory reservation approaches exhaustion. | Nygard (Release It!) |
| **Lease** | **Pronájem (lease)** | A time-bounded grant of authority or lock ownership that expires automatically after a fixed time-to-live unless renewed by the holder. | Gray & Cheriton (SOSP 1989) |
| **Fencing Token** | **Ohraničující token (fencing token)** | A monotonically increasing sequence number issued with each lock or lease acquisition; storage resources reject writes carrying a token lower than the highest token already observed. | Kleppmann (Designing Data-Intensive Applications) |
| **Namespace** | **Jmenný prostor (namespace)** | A Linux kernel isolation primitive that virtualizes global system resources such as process trees, network interfaces, and mount points for a set of processes. | `namespaces(7)` Linux Manual Page |
| **Control Group (cgroup)** | **Řídicí skupina (cgroup)** | A Linux kernel subsystem that limits, accounts for, and isolates the resource usage (CPU, memory, I/O) of a collection of processes. | `cgroups(7)` Linux Manual Page |
| **OverlayFS** | **Překryvný souborový systém (OverlayFS)** | A union mount filesystem that combines a lower read-only image layer and an upper read-write container layer into a unified directory tree. | Linux Kernel Documentation (`overlayfs.txt`) |
| **OCI Image Specification** | **Specifikace obrazu OCI (OCI Image Spec)** | An open industry standard defining the portable format for container images, including manifests, configuration JSON, and content-addressable layers. | Open Container Initiative Image Spec v1.1.1 |
| **OCI Runtime Specification** | **Specifikace runtime OCI (OCI Runtime Spec)** | An open standard defining how to run an unpacked container bundle on disk, including filesystem layout, namespaces, cgroups, and lifecycle hooks. | Open Container Initiative Runtime Spec v1.3.0 |
| **OCI Distribution Specification** | **Specifikace distribuce OCI (OCI Distribution Spec)** | An open standard defining the HTTP/1.1 REST API protocol for uploading and downloading OCI container images and artifacts from registries. | Open Container Initiative Distribution Spec v1.1.1 |
| **runc** | **runc** | The reference implementation of the OCI runtime, responsible for spawning and running containers according to the runtime specification. | OCI Reference Implementation |
| **crun** | **crun** | A fast, lightweight OCI container runtime implemented in C, designed for low memory overhead and integration with systemd and Podman. | `crun` Upstream Project |
| **containerd** | **containerd** | An industry-standard container daemon that manages the complete container lifecycle on a host, from image transfer to execution supervision. | CNCF Project Documentation |
| **Container Shim** | **Mezivrstva kontejneru (shim)** | A lightweight daemon process (`containerd-shim`) that sits between containerd and runc, keeping container I/O and exit status alive independently of the main daemon. | containerd Architecture Documentation |
| **BuildKit** | **BuildKit** | A concurrent, cache-efficient, and extensible backend engine for building OCI container images from Dockerfile sources via Low-Level Builder (LLB) graphs. | Moby / Docker BuildKit Project |
| **Podman** | **Podman** | A daemonless, rootless-native OCI container engine developed by Red Hat for managing pods, containers, and container images without a central daemon. | Podman Documentation |
| **Buildah** | **Buildah** | A specialized command-line utility for creating, building, and modifying OCI container images without requiring a running container daemon. | Buildah Project Documentation |
| **Skopeo** | **Skopeo** | A utility for inspecting, copying, signing, and converting OCI and Docker container images across different registries and storage backends. | Containers Project / Skopeo |
| **veth Pair** | **Pár veth (veth pair)** | Virtual Ethernet device pairs that act as a bidirectional pipe between a network namespace and the host bridge or routing table. | `netdevice(7)` Linux Manual Page |
| **Rootless Container** | **Kontejner bez oprávnění root (rootless container)** | A container running entirely as an unprivileged user on the host by leveraging user namespaces to map UID/GID 0 inside to an unprivileged UID outside. | Rootless Containers Project Standards |
| **Capabilities** | **Oprávnění (capabilities)** | A granular subdivision of the monolithic root privilege model into distinct, independently toggleable privilege flags in the Linux kernel. | `capabilities(7)` Linux Manual Page |
| **Seccomp** | **Seccomp (Secure Computing Mode)** | A Linux kernel security facility that restricts the system calls a process can issue, mitigating kernel attack surface exposure. | `seccomp(2)` Linux Manual Page |
| **Pressure Stall Information (PSI)** | **Informace o tlaku prostředků (PSI)** | Linux kernel metrics measuring resource pressure and task stalling across CPU, memory, and I/O subsystems. | Linux Kernel Documentation (`psi.rst`) |
| **Copy-on-Write (CoW)** | **Kopírování při zápisu (copy-on-write)** | A resource management optimization where multiple callers or forked processes share identical memory or storage pages until a mutation triggers a private page copy. | Operating Systems & Storage Engines |
| **Whiteout File** | **Maskovací soubor výmazu (whiteout file)** | A special character device or opaque attribute used by union filesystems to signal that a file present in a lower layer has been deleted. | OverlayFS Specification |
| **Idmapped Mount** | **Připojení s mapovanými ID (idmapped mount)** | A VFS mount feature allowing files and directories to be accessed with translated UIDs and GIDs without altering underlying on-disk ownership. | Linux Kernel VFS Documentation |
| **Image Manifest** | **Manifest obrazu (image manifest)** | An OCI document listing the content-addressable layers, configuration blob, and media types that compose a specific container image. | OCI Image Specification |
| **Content-Addressable Storage** | **Obsahově adresovatelné úložiště (content-addressable storage)** | A storage architecture where data objects are retrieved exclusively by cryptographic hashes (digests) of their content rather than file paths. | Distributed Systems Architecture |
| **Referrers API** | **API odkazujících objektů (referrers API)** | An OCI Distribution extension allowing artifacts such as signatures and SBOMs to reference a parent image manifest directly via cryptographic digest. | OCI Distribution Specification v1.1 |
| **Low-Level Builder (LLB)** | **Low-Level Builder (LLB / nízkoúrovňový sestavovač)** | BuildKit's intermediate representation graph language representing dependency-ordered build operations asMerkle DAG nodes. | BuildKit Architecture |
| **Quadlet** | **Quadlet** | A systemd integration layer in Podman that translates declarative `.container` initialization files directly into native systemd service units. | Podman Quadlet Documentation |
| **Compose Specification** | **Specifikace Compose (Compose Spec)** | An open multi-vendor standard defining how multi-container application stacks are declared, wired, and orchestrated. | Compose Specification Project (`compose-spec.io`) |
| **SLSA (Supply-chain Levels for Software Artifacts)** | **SLSA** | A security framework consisting of incremental integrity guarantees for software supply chains, from source code to final artifact. | SLSA Security Standards |
| **SBOM (Software Bill of Materials)** | **Seznam softwarových součástí (SBOM)** | A formal structured inventory of software components, libraries, and licenses contained within an artifact. | CISA / Supply-Chain Security Standards |
| **Cosign** | **Cosign** | A tool for signing, verifying, and storing container image signatures and attestations within OCI registries using keyless or key-based OIDC flows. | Sigstore Project |
| **Trivy** | **Trivy** | A comprehensive vulnerability and misconfiguration scanner for container images, file systems, Git repositories, and Kubernetes manifests. | Aqua Security Trivy |
| **Netavark** | **Netavark** | A core network stack manager for Podman and other container engines, replacing older CNI plugins with a streamlined Rust-based backend. | Podman / Netavark Project |
| **Pasta** | **Pasta** | A user-mode networking backend that forwards traffic between host and rootless container network namespaces without requiring root privileges or tap devices. | passt / pasta Project |
