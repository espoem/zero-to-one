# Argo CD & GitOps Glossary (`technologies/argocd`)

Bilingual English-Czech terminology index for GitOps, Argo CD, Argo Rollouts, Argo Workflows, Argo Events, and CNCF certification objectives (CGOA & CAPA).

| English Term | Czech Term | Definition & Context | Primary Reference |
| :-- | :-- | :-- | :-- |
| **Idempotence / Idempotency** | **Idempotence** | The property of an operation where multiple identical executions yield the exact same system state as a single execution (`f(f(x)) = f(x)`). | ISO/IEC 2382, RFC 9110 (HTTP Semantics) |
| **Graceful Shutdown** | **Řádné ukončení služby (graceful shutdown)** | The coordinated termination procedure of stopping new traffic ingestion, draining in-flight requests within a bounded deadline, and releasing persistent connections. | Cloud-Native Operations Standards |
| **Load Shedding** | **Shazování zátěže (load shedding)** | An overload defense mechanism that proactively rejects excess incoming requests when queue depth, event-loop delay, or resource utilization crosses a critical threshold. | Beyer et al. (Site Reliability Engineering) |
| **Circuit Breaker** | **Jistič (circuit breaker)** | A fault-isolation pattern or memory safeguard that trips to fail fast when an upstream dependency degrades or when a node's memory reservation approaches exhaustion. | Nygard (Release It!) |
| **Lease** | **Pronájem (lease)** | A time-bounded grant of authority or lock ownership that expires automatically after a fixed time-to-live unless renewed by the holder. | Gray & Cheriton (SOSP 1989) |
| **Fencing Token** | **Ohraničující token (fencing token)** | A monotonically increasing sequence number issued with each lock or lease acquisition; storage resources reject writes carrying a token lower than the highest token already observed. | Kleppmann (Designing Data-Intensive Applications) |
| **GitOps** | **GitOps** | An operational framework that takes DevOps best practices such as version control, collaboration, compliance, and CI/CD automation, and applies them to infrastructure and application configuration. | OpenGitOps Project / CNCF |
| **Declarative System** | **Deklarativní systém** | A system where users specify the desired target state of resources rather than imperative procedural steps to achieve it. | OpenGitOps Principles v1.0.0 |
| **Reconciliation Loop** | **Smyčka usmiřování (reconciliation loop)** | A control loop that continuously compares actual live system state against desired declarative state and applies corrections to eliminate drift. | Kubernetes Controller Pattern & Argo CD |
| **Drift Detection** | **Detekce odchylek (drift detection)** | The automated process of identifying discrepancies between live cluster resources and desired state declared in Git repositories. | Argo CD Application Controller |
| **Sync Wave** | **Synchronizační vlna (sync wave)** | An integer-valued annotation (`argocd.argoproj.io/sync-wave`) used to order resource creation and updates during an Argo CD synchronization phase. | Argo CD User Guide |
| **Sync Hook** | **Synchronizační hák (sync hook)** | A temporary Kubernetes job or resource executed at specific lifecycle points (`PreSync`, `Sync`, `PostSync`, `SyncFail`) during an Argo CD sync operation. | Argo CD User Guide |
| **Application** | **Aplikace (Application CRD)** | The primary Argo CD Custom Resource defining a target repository source, destination cluster/namespace, and synchronization policies. | Argo CD CRD Specification |
| **AppProject** | **Projekt aplikace (AppProject CRD)** | A multi-tenancy grouping construct in Argo CD restricting allowed source repositories, destination namespaces, and cluster resource kinds. | Argo CD Multi-Tenancy Architecture |
| **ApplicationSet** | **Sada aplikací (ApplicationSet CRD)** | An Argo CD controller extension that automates the generation of multiple Argo CD `Application` resources from generators (List, Cluster, Git, Matrix). | Argo CD ApplicationSet Controller |
| **Source Hydrator** | **Hydratátor zdrojů (source hydrator)** | A pattern and Argo CD feature where raw upstream Helm charts or Kustomize templates are rendered into plain manifests stored in Git before cluster deployment. | Argo CD v3.5 Architecture |
| **Server-Side Apply (SSA)** | **Aplikace na straně serveru (SSA)** | Kubernetes API mechanism enabling declarative field management, multi-manager tracking, and conflict resolution without client-side three-way merge. | Kubernetes API Conventions (KEP-555) |
| **Progressive Delivery** | **Progresivní doručování** | Deployment methodology that releases software changes to a small subset of users first, monitoring metrics before progressively rolling out to 100% of traffic. | Continuous Delivery & Argo Rollouts |
| **Canary Deployment** | **Kanárkové nasazení (canary deployment)** | A deployment strategy where a new version runs alongside the stable version, receiving a fraction of production traffic while automated metrics analyze success. | Martin Fowler / Argo Rollouts |
| **Blue/Green Deployment** | **Modro-zelené nasazení (blue/green deployment)** | A release management pattern maintaining two identical production environments (Blue and Green), switching router traffic instantaneously upon validation. | Continuous Delivery Patterns |
| **AnalysisTemplate** | **Šablona analýzy (AnalysisTemplate CRD)** | An Argo Rollouts custom resource defining metrics queries (Prometheus, Web, Datadog) and success criteria for canary evaluation. | Argo Rollouts Documentation |
| **AnalysisRun** | **Spuštění analýzy (AnalysisRun CRD)** | An instantiated execution of an `AnalysisTemplate` evaluated during a progressive delivery rollout step. | Argo Rollouts Documentation |
| **Config Management Plugin (CMP)** | **Zásuvný modul správce konfigurace (CMP)** | A sidecar container in Argo CD repo-server used to execute custom manifest generation tools beyond built-in Helm, Kustomize, or ksonnet. | Argo CD Operator Manual |
| **Ignore Differences** | **Ignorování rozdílů** | An Argo CD configuration directive (`ignoreDifferences`) instructing the controller to ignore specific JSON path fields subject to external mutation (e.g., HPA replicas). | Argo CD User Guide |
| **Self-Heal** | **Samoozdravení (self-heal)** | An optional Argo CD sync policy that automatically forces synchronization when cluster-side drift is detected against Git desired state. | Argo CD User Guide |
| **Prune** | **Prořezávání / čištění (prune)** | An Argo CD synchronization option that deletes live Kubernetes resources that no longer exist in the desired Git manifest source. | Argo CD User Guide |
| **App-of-Apps** | **Aplikace aplikací (App-of-Apps pattern)** | A bootstrapping pattern where a master Argo CD `Application` manages other Argo CD `Application` manifests. | Argo CD Design Patterns |
| **Dex OIDC** | **Dex OIDC server** | An identity service integrated into Argo CD that federates external identity providers (GitHub, Google, LDAP, OIDC) into Kubernetes RBAC sessions. | Argo CD Authentication Guide |
| **Casbin RBAC** | **Casbin řízení přístupu (Casbin RBAC)** | An access-control model utilized by Argo CD (`argocd-rbac-cm`) implementing fine-grained authorization policies based on subjects, domains, objects, and actions. | Casbin Access Control Framework |
| **Repo Server** | **Repozitářový server (repo-server)** | The stateless Argo CD microservice responsible for cloning Git repositories, fetching Helm charts, and generating manifests. | Argo CD Architecture |
| **Application Controller** | **Kontroler aplikací (application-controller)** | The stateful Argo CD core reconciliation engine responsible for comparing Git desired state with live Kubernetes cluster state. | Argo CD Architecture |
| **Argo Workflows** | **Pracovní postupy Argo (Argo Workflows)** | A container-native workflow engine for Kubernetes supporting Directed Acyclic Graphs (DAGs) and step-based pipelines. | Argo Workflows Documentation |
| **Argo Events** | **Události Argo (Argo Events)** | An event-driven dependency manager for Kubernetes connecting event sources (webhooks, S3, PubSub) to Argo Workflows or serverless triggers. | Argo Events Documentation |
| **GitOps Promoter** | **Propagátor GitOps (GitOps promoter)** | A pipeline tool or pattern automating version promotion across environment branches or directories (e.g., dev $\to$ staging $\to$ prod). | GitOps Best Practices |
| **Image Updater** | **Aktualizátor obrazů (Argo CD Image Updater)** | An auxiliary controller that automatically detects new container registry image tags and updates Git repositories accordingly. | Argo CD Image Updater Manual |
| **Resource Exclusion** | **Vyloučení zdrojů (resource exclusion)** | An Argo CD configuration setting (`resource.exclusions`) preventing the application controller from monitoring specific cluster-scoped or namespaced CRDs. | Argo CD Operator Manual |
| **Hard Refresh** | **Úplné obnovení (hard refresh)** | An administrative command (`argocd app get --hard-refresh`) forcing the repo-server to bypass its cache and re-clone repositories to fetch latest commits. | Argo CD CLI Reference |
| **Orphaned Resources** | **Opuštěné zdroje (orphaned resources)** | Live Kubernetes resources that were previously managed by an Argo CD Application but whose tracking references or labels were removed. | Argo CD User Guide |
| **Resource Tracking** | **Sledování zdrojů (resource tracking)** | The mechanism Argo CD uses to map deployed Kubernetes objects back to their owning Application (`argocd.argoproj.io/tracking-id` or labels). | Argo CD Architecture |
| **Webhook Receiver** | **Příjemce webhooků (webhook receiver)** | The Argo CD API server endpoint that listens for repository push notifications to trigger immediate application reconciliation without waiting for polling intervals. | Argo CD API Documentation |
