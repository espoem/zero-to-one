# Python Glossary (EN ↔ CZ)

This glossary defines standard technical terms used throughout the `languages/python/` learning track. All definitions and context descriptions are written in English; terms provide their canonical English name and established Czech equivalent. Terminology is grounded in the official Python Language Reference, Python Enhancement Proposals (PEPs), CPython internal architecture, and authoritative reference literature.

---

## 1. Execution Model, Bytecode & CPython Internals

| English Term | Czech Term | Definition & Context | Primary Reference |
| :--- | :--- | :--- | :--- |
| **Abstract Syntax Tree (AST)** | **Abstraktní syntaktický strom** | A tree representation of the abstract syntactic structure of source code, generated by the parser and transformed by the symbol table pass before bytecode emission. | Python `ast` module docs |
| **Bytecode** | **Bajtový kód (bajt kód)** | The intermediate, platform-independent instruction set executed by the CPython virtual machine evaluation loop (`_PyEval_EvalFrameDefault`). | Python Glossary |
| **Wordcode** | **Wordcode (16bitové instrukce)** | CPython's 16-bit instruction format (1 byte opcode, 1 byte oparg), simplifying jump offsets and cache-line decoding. | PEP 511 / Python 3.6+ |
| **Specializing Adaptive Interpreter** | **Specializující adaptivní interpret** | CPython's inline JIT-like bytecode specialization engine (PEP 659) that dynamically replaces generic opcodes with monomorphic quickened variants based on runtime type stability. | PEP 659 |
| **Zero-Cost Exception Tables** | **Nulocenové tabulky výjimek** | An exception-handling implementation where `try` blocks incur zero runtime overhead during the happy path; exception handler lookup tables are stored separately in the code object. | Python 3.11 Release Notes |
| **PyObject** | **PyObject (základní C struktura objektu)** | The fundamental C struct header for all Python objects in CPython, containing `ob_refcnt` (reference counter) and `ob_type` (pointer to the type object). | Python C API Reference |
| **Reference Counting** | **Počítání referencí** | The primary deterministic memory management mechanism in CPython: every object maintains an `ob_refcnt` counter that immediately deallocates the object when it drops to zero. | Python Dev Guide |
| **Cyclic Garbage Collector** | **Cyklický garbage collector (správce cyklů)** | The secondary generational mark-and-sweep garbage collector in CPython that detects and reclaims unreferenced circular reference graphs between container objects. | Python `gc` module docs |
| **Generational Hypothesis** | **Generační hypotéza** | The heuristic observation that most allocated objects die young; CPython categorizes tracked objects into three generations (Gen 0, 1, 2) to minimize full heap sweeps. | CPython `gc.c` internals |
| **Trial Deletion** | **Zkušební mazání (algoritmus detekce cyklů)** | The cycle detection algorithm in CPython: decrements temporary reference counters (`gc_refs`) for all references within a generation to find isolated circular subgraphs. | CPython Garbage Collection Internals |
| **Immortal Objects** | **Nesmrtelné objekty** | Runtime singletons (`None`, `True`, `False`, small ints) whose reference counts are pinned to a permanent sentinel value, eliminating cache-line invalidation in Copy-on-Write forks. | PEP 683 |
| **`pymalloc`** | **`pymalloc` (alokátor malých objektů)** | CPython's specialized small-object allocator; uses 256KB arenas, 4KB pools, and fixed size classes for memory allocations $\le 512$ bytes to avoid libc `malloc` fragmentation. | Python C API Reference |

## 2. Object Model & Dunder Protocols

| English Term | Czech Term | Definition & Context | Primary Reference |
| :--- | :--- | :--- | :--- |
| **Dunder Methods (Magic Methods)** | **Dunder metody (magické metody)** | Special methods surrounded by double underscores (e.g. `__init__`, `__repr__`) that CPython invokes under the hood to implement language protocols and operator overloading. | Python Data Model |
| **Hash Invariant** | **Invariant hešování** | The mathematical contract requiring that if two objects compare equal ($a == b$), their hash values must be identical ($\text{hash}(a) == \text{hash}(b)$). | Python Data Model (`__hash__`) |
| **Unhashable Type** | **Nehešovatelný typ** | A mutable or custom type that sets `__hash__ = None`, signaling to the interpreter that instances cannot be used as dictionary keys or set members. | Python Data Model |
| **`__slots__`** | **`__slots__` (pevné sloty atributů)** | A class attribute declaration that replaces dynamic per-instance `__dict__` hash tables with fixed C-level descriptor offsets, optimizing memory and attribute access speed. | Python Reference Manual |
| **Reflected Operations** | **Reflektované operace (obrácené operátory)** | Arithmetic protocol methods (e.g. `__radd__`, `__rsub__`) invoked on the right-hand operand when the left-hand operand returns `NotImplemented`. | Python Data Model |
| **`NotImplemented`** | **`NotImplemented` (singlton nepodporované operace)** | A special runtime singleton returned by binary comparison and arithmetic dunder methods to signal that an operand combination is unsupported, delegating to the reflected method. | Python Built-in Constants |
| **`__init_subclass__`** | **`__init_subclass__` (háček inicializace podtřídy)** | A class hook (PEP 487) invoked whenever a parent class is subclassed, enabling declarative validation and registration without metaclass overhead. | PEP 487 |

## 3. Descriptors, Metaclasses & Scoping

| English Term | Czech Term | Definition & Context | Primary Reference |
| :--- | :--- | :--- | :--- |
| **Data Descriptor** | **Datový deskriptor** | A descriptor object defining `__get__` and at least one of `__set__` or `__delete__`; takes precedence over instance `__dict__` during attribute lookup. | Descriptor HowTo Guide |
| **Non-Data Descriptor** | **Nedatový deskriptor** | A descriptor object defining only `__get__` (e.g. standard functions and methods); can be shadowed by an entry in the instance's `__dict__`. | Descriptor HowTo Guide |
| **`__set_name__`** | **`__set_name__` (registrace jména deskriptoru)** | A descriptor callback (PEP 487) invoked at class creation time, providing the descriptor instance with the attribute name and class it was bound to. | PEP 487 |
| **Method Resolution Order (MRO)** | **Pořadí vyhodnocování metod (MRO)** | The linear sequence of classes traversed when resolving attributes and method calls in multiple inheritance hierarchies. | Python Language Reference |
| **C3 Linearization** | **C3 linearizace** | The monotonic linearization algorithm used by Python to compute MRO, ensuring that local precedence order and monotonicity are strictly preserved. | Python MRO Documentation |
| **Cooperative Multiple Inheritance** | **Kooperativní vícenásobná dědičnost** | The design pattern where classes in a diamond hierarchy call `super().__init__()` cooperatively, ensuring every class in the MRO is visited exactly once. | Raymond Hettinger: *Super Considered Super* |
| **Metaclass** | **Metatřída** | The "class of a class"; a type that defines how classes themselves are constructed, instantiated, and modified during class definition evaluation. | Python Data Model |
| **LEGB Rule** | **Pravidlo LEGB (rozsahy platnosti)** | The lexical variable lookup order in Python: Local $\to$ Enclosing $\to$ Global $\to$ Builtins. | Python Execution Model |
| **Late-Binding Closure** | **Uzávěra s pozdní vazbou** | The behavior where closures look up variable names at invocation time rather than binding the variable's value at closure definition time. | Python Programming FAQ |

## 4. Iteration, Generators & Concurrency

| English Term | Czech Term | Definition & Context | Primary Reference |
| :--- | :--- | :--- | :--- |
| **Iterator Protocol** | **Protokol iterátoru** | The protocol requiring `__iter__()` returning `self` and `__next__()` returning the next item or raising `StopIteration`. | PEP 234 |
| **Generator Function** | **Generátorová funkce** | A function containing `yield` expressions that produces a lazy generator iterator suspended in memory between calls. | PEP 255 |
| **`yield from`** | **`yield from` (delegace na podgenerátor)** | Syntax (PEP 380) establishing a transparent bidirectional communication channel between the caller and an inner sub-generator. | PEP 380 |
| **Context Manager Protocol** | **Protokol správce kontextu** | The resource management protocol requiring `__enter__()` and `__exit__()`, executed deterministically via `with` statements. | PEP 343 |
| **`ExceptionGroup`** | **Skupina výjimek (`ExceptionGroup`)** | A composite exception container (PEP 654) holding multiple concurrent or grouped exceptions, handled via `except*` syntax. | PEP 654 |
| **Global Interpreter Lock (GIL)** | **Globální zámek interpretu (GIL)** | The mutex in standard CPython that prevents multiple native OS threads from executing Python bytecodes concurrently. | Python Wiki |
| **Free-Threaded CPython** | **CPython bez GILu (volně vláknový)** | The CPython build configuration (PEP 703) that removes the GIL, utilizing biased reference counting and mimalloc to enable true multi-core thread execution. | PEP 703 / PEP 779 |
| **Subinterpreters** | **Podinterprety (subinterprety)** | Isolated execution environments within a single process (PEP 684/734) that possess their own GILs, enabling concurrent execution across OS threads. | PEP 684 / PEP 734 |
| **Reactor Pattern** | **Návrhový vzor Reaktor** | The concurrency design pattern implemented by `asyncio`, where an event loop monitors I/O sockets and dispatches events to registered callbacks and coroutines. | POSIX / asyncio docs |
| **Structured Concurrency** | **Strukturované souběžné programování** | A concurrency paradigm (`asyncio.TaskGroup`) guaranteeing that concurrent tasks have bounded lifecycles strictly nested within lexical scopes, preventing orphaned background tasks. | PEP 654 / asyncio docs |
| **Backpressure** | **Zpětný tlak (backpressure)** | A flow control mechanism where a downstream consumer signals an upstream producer to pause emission (e.g. bounded `asyncio.Queue` with `maxsize`). | Reactive Systems Principles |

## 5. Type System & Annotations

| English Term | Czech Term | Definition & Context | Primary Reference |
| :--- | :--- | :--- | :--- |
| **PEP 695 Type Parameters** | **Typové parametry (PEP 695)** | Native syntax (`class Box[T]:`, `type Alias[T] = ...`) integrating generics directly into the Python grammar without requiring `TypeVar` boilerplate. | PEP 695 |
| **Subtyping Variance** | **Variance podtypů** | The relationship between the subtyping of complex generic types ($F[A]$ and $F[B]$) and the subtyping of their component types ($A$ and $B$). | TAPL / PEP 484 |
| **Invariance** | **Invariance** | A variance rule where $F[A]$ and $F[B]$ have no subtyping relationship unless $A \equiv B$; required for all mutable collections (e.g. `list[T]`). | PEP 484 |
| **Covariance** | **Kovariance** | A variance rule where $A <: B \implies F[A] <: F[B]$; valid for read-only producer collections (e.g. `Sequence[T]`). | PEP 484 |
| **Contravariance** | **Kontravariance** | A variance rule where $A <: B \implies F[B] <: F[A]$; valid for write-only consumer arguments (e.g. callable parameter types). | PEP 484 |
| **`TypeIs[T]`** | **Obousměrné zúžení typu (`TypeIs`)** | A typing construct (PEP 742) establishing bidirectional type narrowing: narrows to $T$ in the `True` branch and removes $T$ from the union in the `False` branch. | PEP 742 |
| **`TypeGuard[T]`** | **Uživatelský strážce typu (`TypeGuard`)** | A legacy typing construct (PEP 647) that narrows a type only in the positive `True` branch, leaving the `False` branch un-narrowed. | PEP 647 |
| **Structural Typing (Protocol)** | **Strukturální typování (`typing.Protocol`)** | Static duck-typing (PEP 544) where type compatibility is determined by an object's methods and attributes rather than explicit class inheritance. | PEP 544 |
| **`ParamSpec`** | **Specifikace parametrů (`ParamSpec`)** | A type variable (PEP 612) that captures callable parameter packs, enabling static typing of decorators with signature preservation. | PEP 612 |
| **Deferred Annotations** | **Odložené vyhodnocování anotací** | The mechanism (PEP 649/749) compiling type annotations into a lazy `__annotate__` code object rather than evaluating them at module import time. | PEP 649 / PEP 749 |
