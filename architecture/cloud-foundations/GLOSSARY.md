# Cloud Foundations Glossary

Bilingual English ↔ Czech terminology index for the **Cloud Foundations** architecture track, covering multi-cloud models, distributed governance, IAM, virtual networking, reliability engineering, Well-Architected frameworks, and FinOps.

> [!IMPORTANT]
> Terms shared with the root glossary (`Idempotence / Idempotency`, `Backpressure`, `Graceful Shutdown`, `Load Shedding`, `Circuit Breaker`, `Lease`, `Fencing Token`, `CAP Theorem`, `Eventual Consistency`, `ACID`, `BASE`) are copied verbatim from root `GLOSSARY.md`.

| English Term | Czech Term | Definition & Context | Primary Reference |
| :-- | :-- | :-- | :-- |
| **Shared Responsibility Model** | **Model sdílené odpovědnosti** | A security and operational division of obligations between the cloud service provider (security _of_ the cloud: physical hardware, hypervisors, global infrastructure) and the cloud consumer (security _in_ the cloud: guest OS, network rules, IAM, data classification, and encryption). | NIST SP 800-145, Cloud Security Alliance (CSA) |
| **Static Stability** | **Statická stabilita** | The architectural quality where a distributed workload continues operating normally without taking state changes, relying on control plane mutations, or initiating external API calls during upstream outages or control plane failures. | Amazon Builders' Library, Distributed Systems Architecture |
| **Blast Radius** | **Rádius zásahu / dopadu** | The maximum bounded domain of systems, accounts, regions, or customers that can be degraded or disrupted when a single operational failure, bug, or configuration mistake occurs. | AWS Well-Architected Framework, SRE Principles |
| **Control Plane vs. Data Plane** | **Řídicí rovina vs. datová rovina** | The architectural separation between the components executing administrative commands, configuration mutations, and orchestration (control plane) and the components handling customer payload packets, transactions, and I/O (data plane). | RFC 7426, Systems Architecture |
| **Preventive Guardrail** | **Preventivní mantinel / bezpečnostní zábrana** | An authoritative, mandatory policy constraint enforced prior to resource creation (e.g., AWS SCPs, GCP Organization Policies, Azure Policy Deny effect) that mechanically rejects non-compliant configuration requests. | NIST SP 800-210, Cloud Governance Standards |
| **Detective Guardrail** | **Detekční mantinel** | An automated monitoring and auditing mechanism (e.g., AWS Config, Security Hub, Azure Policy Audit) that identifies non-compliant resources after deployment and triggers alert notifications or automated remediation workflows. | NIST SP 800-210, Cloud Compliance Frameworks |
| **Landing Zone** | **Přistávací zóna (landing zone)** | A multi-account, well-architected cloud environment configured with automated baseline security, identity federation, centralized network hub, log aggregation, and compliance guardrails. | AWS Control Tower, Microsoft Cloud Adoption Framework |
| **Service Control Policy (SCP)** | **Pravidla řízení služeb (SCP)** | A type of organization policy in AWS Organizations used to manage permissions in an organization, defining an immutable permission boundary across accounts and organizational units (OUs). | AWS Identity Documentation |
| **Resource Control Policy (RCP)** | **Pravidla řízení prostředků (RCP)** | An organization-level authorization guardrail in AWS enforcing data perimeter boundaries and restricting inbound/outbound access on AWS resources across accounts. | AWS Security Documentation |
| **Workload Identity Federation** | **Federace identit pracovních zátěží** | An authentication mechanism allowing external workloads (e.g., GitLab CI/CD, Kubernetes pods) to exchange short-lived OIDC JWT assertions for cloud STS credentials without embedding static API access keys. | OAuth 2.0 Token Exchange (RFC 8693), SPIFFE Standards |
| **Confused Deputy Problem** | **Problém zmateného zástupce** | A security vulnerability where an authorized service entity is tricked by a malicious caller into abusing its elevated privileges to access a third party's resources (mitigated via external IDs and context keys). | Norm Hardy (1988), NIST SP 800-210 |
| **Least Privilege** | **Princip nejmenších privilegií** | The security principle requiring that every module, user, and workload must be granted only the minimum permissions necessary to perform its legitimate function. | Saltzer & Schroeder (1975) |
| **Virtual Private Cloud (VPC)** | **Virtuální privátní síť (VPC / VNet)** | A logically isolated virtual network allocated to a cloud account, configurable with private IP address ranges, subnets, route tables, and network security gateways. | Cloud Networking Standards |
| **Classless Inter-Domain Routing (CIDR)** | **Beztřídní směrování (CIDR)** | An IP addressing allocation methodology utilizing variable-length subnet masking (`/mask`) to divide address spaces flexibly without rigid address classes. | RFC 4632, Internet Engineering Task Force |
| **VPC Peering** | **Propojení VPC (peering)** | A non-transitive direct network connection between two VPCs allowing routing using private IPv4/IPv6 addresses without public internet transit or VPN gateways. | Cloud Networking Standards |
| **Private Endpoint / PrivateLink** | **Soukromý koncový bod (private endpoint)** | A network interface with a private IP address within a customer's VPC enabling secure, private ingress to external PaaS or SaaS services over the provider's private backbone. | AWS PrivateLink, Azure Private Link, GCP PSC |
| **NAT Gateway** | **Brána pro překlad síťových adres (NAT gateway)** | A managed network service allowing private subnet instances to initiate outbound connections to the internet while preventing unsolicited inbound traffic from the outside internet. | RFC 3022, Cloud Networking Standards |
| **Cell-Based Architecture** | **Buňková architektura** | A distributed systems design pattern that partitions a platform into multiple independent, complete, self-contained instances called cells, strictly containing systemic failure within a single cell. | AWS Architecture Center, Google SRE |
| **Shuffle Sharding** | **Náhodné sdílené rozprostření (shuffle sharding)** | A virtual partitioning technique assigning each tenant a deterministic subset of physical nodes from a shared pool, exponentially multiplying fault isolation domains without adding physical hardware. | Amazon Builders' Library |
| **Object Storage Durability vs. Availability** | **Trvanlivost vs. dostupnost objektového úložiště** | Durability measures the annual probability that an object stored in the system is not lost or corrupted (e.g., 11×9s = 99.999999999%); availability measures the uptime probability that an object can be read when requested (e.g., 99.9%). | Cloud Storage Architecture |
| **Object Lock / WORM** | **Uzamčení objektů / WORM (Write Once, Read Many)** | A regulatory compliance feature enforcing immutability on stored objects, preventing modification or deletion by any user (including root/admin) during a retention window. | SEC Rule 17a-4, Finra Standards |
| **Recovery Point Objective (RPO)** | **Cílový bod obnovy (RPO)** | The maximum acceptable data loss tolerance measured backward in time from a disaster event to the most recent committed and recoverable transaction. | Disaster Recovery Standards |
| **Recovery Time Objective (RTO)** | **Cílový čas obnovy (RTO)** | The maximum acceptable duration of time permitted to restore full service functionality after an outage or disaster declaration. | Disaster Recovery Standards |
| **Poison Message** | **Jedovatá zpráva (poison message)** | A malformed or unprocessable message that repeatedly causes the consumer service to crash or throw unhandled exceptions upon receipt. | Enterprise Integration Patterns |
| **Dead Letter Queue (DLQ)** | **Fronta nezpracovatelných zpráv (DLQ)** | A secondary queue to which messages that exceed a configured maximum retry delivery threshold are diverted for offline inspection and triage. | Message-Oriented Middleware Architecture |
| **Visibility Timeout** | **Časový limit viditelnosti zprávy** | The time window during which a message dequeued by a worker remains invisible to other workers; if not acknowledged before timeout expiry, it becomes visible again for redelivery. | Amazon SQS Architecture, Cloud Messaging |
| **Distributed Saga Pattern** | **Vzor distribuované ságy (saga)** | A distributed transaction management pattern coordinating multi-service workflows via a sequence of local transactions, rolling back failures via executing compensating actions in reverse order. | Garcia-Molina & Salem (1987) |
| **Compensating Transaction** | **Kompenzační transakce** | An operation that logically undoes the side effects of a previously committed local step within an aborted saga workflow. | Distributed Database Systems |
| **Retry Storm** | **Lavina opakovaných pokusů (retry storm)** | A cascading failure mode where multiple client or service tiers synchronously retry failing requests simultaneously, overwhelming recovering backends with exponential traffic spikes. | SRE Incident Management |
| **FinOps** | **Finanční operace v cloudu (FinOps)** | The operational discipline and cultural practice of cloud cost optimization that brings financial accountability to the variable spend model of cloud infrastructure. | FinOps Foundation Framework |
| **Showback vs. Chargeback** | **Vyúčtování pro informaci vs. interní přeúčtování** | Showback presents granular cloud resource cost reports to business teams for visibility and awareness; chargeback directly debits those costs against individual department budgets. | FinOps Practice Standards |
| **Unit Economics** | **Jednotková ekonomika** | The measurement of cloud infrastructure cost normalized per business output metric (e.g., cloud spend per active user, per checkout transaction, or per streamed video hour). | FinOps & Product Management |
| **Policy-as-Code** | **Politika jako kód (Policy-as-Code)** | The practice of writing, testing, versioning, and enforcing security, operational, and architectural compliance rules using declarative code and automated CI/CD pipelines. | OPA / Rego, Terraform Policy |
| **Idempotence / Idempotency** | **Idempotence** | The property of an operation where multiple identical executions yield the exact same system state as a single execution (`f(f(x)) = f(x)`). | ISO/IEC 2382, RFC 9110 (HTTP Semantics) |
| **Backpressure** | **Zpětný tlak (_backpressure_)** | The flow-control protocol where a slow consumer signals an upstream producer that intermediate buffers are full, pausing or throttling production until capacity drains. | Reactive Streams Specification, Node.js Streams |
| **Graceful Shutdown** | **Řádné ukončení služby (graceful shutdown)** | The coordinated termination procedure of stopping new traffic ingestion, draining in-flight requests within a bounded deadline, and releasing persistent connections. | Cloud-Native Operations Standards |
| **Load Shedding** | **Shazování zátěže (load shedding)** | An overload defense mechanism that proactively rejects excess incoming requests when queue depth, event-loop delay, or resource utilization crosses a critical threshold. | Beyer et al. (Site Reliability Engineering) |
| **Circuit Breaker** | **Jistič (circuit breaker)** | A fault-isolation pattern or memory safeguard that trips to fail fast when an upstream dependency degrades or when a node's memory reservation approaches exhaustion. | Nygard (Release It!) |
| **Lease** | **Pronájem (lease)** | A time-bounded grant of authority or lock ownership that expires automatically after a fixed time-to-live unless renewed by the holder. | Gray & Cheriton (SOSP 1989) |
| **Fencing Token** | **Ohraničující token (fencing token)** | A monotonically increasing sequence number issued with each lock or lease acquisition; storage resources reject writes carrying a token lower than the highest token already observed. | Kleppmann (Designing Data-Intensive Applications) |
| **CAP Theorem** | **CAP teorém (Brewerův teorém)** | A fundamental theorem stating that a distributed data store can simultaneously provide at most two of three guarantees: Consistency, Availability, and Partition Tolerance. | Brewer, Gilbert & Lynch |
| **Eventual Consistency** | **Konečná konzistence** | A consistency model where, in the absence of new updates, all replicas eventually converge to the same value. | Vogels (Eventually Consistent) |
| **ACID** | **ACID (Atomicity, Consistency, Isolation, Durability)** | A suite of four standard properties guaranteeing that database transactions are processed reliably. | Haerder & Reuter |
| **BASE** | **BASE (Basically Available, Soft state, Eventual consistency)** | An architectural model prioritizing high availability over immediate consistency in distributed environments. | Pritchett |
