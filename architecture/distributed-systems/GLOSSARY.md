# Bilingual Glossary: Distributed Systems (English ↔ Czech)

This glossary establishes canonical terminology for distributed systems, consensus algorithms, replication protocols, consistency models, and fault-tolerant architecture. Definitions are written in rigorous technical English accompanied by established Czech academic and industry terminology, anchored in primary computer science literature (Lamport, Fischer-Lynch-Paterson, Herlihy & Wing, Ongaro & Ousterhout, Gray, Shapiro, and Kleppmann).

---

## Terminology Index

| English Term | Czech Equivalent | Concise Technical Definition | Primary Authority |
|---|---|---|---|
| **Asynchronous Network** | Asynchronní síť | A network timing model where message transmission delays and processing execution times are finite but completely unbounded. | Fischer, Lynch, Paterson (1985) |
| **At-Least-Once Delivery** | Doručení alespoň jednou | A messaging guarantee where every message is delivered to the recipient one or more times; requires application-layer deduplication to avoid duplicate side effects. | Saltzer, Reed, Clark (End-to-End 1984) |
| **At-Most-Once Delivery** | Doručení nejvýše jednou | A messaging guarantee where messages are delivered zero or one time, preventing duplicate processing at the risk of message loss during network failures. | Birrell & Nelson (RPC 1984) |
| **Atomic Broadcast (Total Order Broadcast)** | Atomické všesměrové vysílání (uspořádané vysílání) | A communication primitive guaranteeing that all non-faulty nodes deliver the exact same sequence of messages in the identical order. Equivalent to distributed consensus. | Hadzilacos & Toueg (1994), Defago et al. (2004) |
| **Atomic Commit** | Atomické potvrzení | A protocol ensuring that a transaction executes across multiple autonomous participants such that either all participants commit the updates or all abort them. | Gray (1978), Skeen (1981) |
| **Byzantine Fault** | Byzantská chyba | An arbitrary or adversarial failure mode where a node may exhibit arbitrary behavior, including sending conflicting messages to different peers, forging data, or lying about state. | Lamport, Shostak, Pease (1982) |
| **CAP Theorem** | CAP věta | A foundational result proving that a distributed read/write register cannot simultaneously guarantee Consistency (linearizability) and Availability in the presence of Network Partitions. | Fox & Brewer (1999), Gilbert & Lynch (2002) |
| **Causal Consistency** | Kauzální konzistence | A consistency model guaranteeing that operations causally related by the happens-before relation ($\to$) are observed in the same order by all processes; concurrent operations may be observed in different orders. | Lamport (1978), Ahamad et al. (1995) |
| **Chain Replication** | Řetězcová replikace | A primary-backup replication protocol where nodes are arranged linearly; writes enter at the Head and propagate down to the Tail, while linearizable reads are served exclusively from the Tail. | van Renesse & Schneider (OSDI 2004) |
| **Check-Quorum** | Kontrola kvóra | A Raft mechanism where a leader steps down to follower state if it fails to receive heartbeats from a majority of nodes within one election timeout, preventing zombie leaders. | Ongaro (Stanford PhD Thesis 2014) |
| **Conflict-Free Replicated Data Type (CRDT)** | Datový typ replikovaný bez konfliktů | A distributed data structure whose replicas can be updated concurrently without central coordination and merged deterministically into identical states using join-semilattice properties. | Shapiro et al. (INRIA 2011) |
| **Consensus** | Distribuovaný konsensus | The fundamental problem where a group of processes must agree on a single value satisfying Agreement, Validity, Integrity, and Termination. | Pease, Shostak, Lamport (1980) |
| **Crash-Recovery Fault** | Chyba typu pád a zotavení | A fault model where nodes may unexpectedly stop executing, but can later recover with their non-volatile disk state intact and resume participation. | Lynch (Distributed Algorithms 1996) |
| **Crash-Stop Fault (Fail-Stop)** | Chyba typu pád a zastavení | A fault model where a node halts execution and remains halted permanently, with failures reliably detectable in synchronous systems. | Schlichting & Schneider (1983) |
| **Deterministic Simulation Testing (DST)** | Deterministické simulační testování | A verification methodology where an entire distributed cluster is executed within a single thread using virtualized time, network, and disk I/O driven by a pseudo-random seed for 100% replayability. | Zhou et al. (FoundationDB, SIGMOD 2021) |
| **Distributed Lock** | Distribuovaný zámek | A coordination primitive granting exclusive access to a shared resource across multiple independent processes over a network. | Gray (1978), Burrows (Chubby, OSDI 2006) |
| **Dueling Proposers** | Souboj navrhovatelů (livelock) | A livelock condition in Paxos where two proposers alternate sending higher `Prepare` requests, continually preempting each other's Phase 2 `Accept` rounds before consensus can complete. | Lamport (Paxos Made Simple 2001) |
| **Epoch / Term** | Epocha / Volební období | A monotonically increasing logical sequence number demarcating a period of leadership in consensus protocols (e.g., Raft term, ZAB epoch, Paxos ballot/view). | Ongaro & Ousterhout (2014) |
| **Eventual Consistency** | Koncová (případná) konzistence | A weak liveness guarantee that if no further updates are made to an object, all replicas will eventually converge to identical values. | Vogels (ACM Queue 2008) |
| **Fencing Token** | Ohrazovací token (fencing token) | A monotonically increasing number issued by a lock service; storage nodes reject writes tagged with a token lower than the highest token observed, preventing stale lock holders from corrupting data. | Kleppmann (2016) |
| **Flexible Paxos** | Flexibilní Paxos | An extension of Paxos proving that quorums within Phase 1 and Phase 2 need not be majorities; safety holds as long as any Phase 1 quorum intersects any Phase 2 quorum by at least one node ($Q_1 \cap Q_2 \neq \emptyset$). | Howard, Malkhi, Spiegelman (2016) |
| **FLP Impossibility** | Nemocnost FLP (nemožnost dosažení konsensu) | The theorem proving that no deterministic consensus algorithm can guarantee liveness (termination) in an asynchronous network in the presence of even a single unannounced crash fault. | Fischer, Lynch, Paterson (JACM 1985) |
| **Happens-Before Relation ($\to$)** | Relace stalo-se-před | A strict partial ordering of events in a distributed system based on process-local order and message send-receive causality. | Lamport (CACM 1978) |
| **High Watermark (HW)** | Vysoká vodoznaková značka | In distributed commit logs (such as Kafka), the highest offset replicated across all in-sync replicas (ISR), representing the boundary of messages safe for consumer reads. | Kreps (I Heart Logs 2014) |
| **Hybrid Logical Clock (HLC)** | Hybridní logické hodiny | A clock combining physical wall-clock time with logical sequence counters, maintaining Lamport causality while remaining bounded within maximum NTP drift $\epsilon$ of physical time. | Kulkarni et al. (2014) |
| **Idempotence** | Idempotence | The property of an operation where applying it multiple times produces the identical side effect and state as applying it once ($f(f(x)) = f(x)$). | Standard Computer Science |
| **In-Sync Replicas (ISR)** | Množina synchronizovaných replik | The dynamically tracked subset of Kafka topic partition replicas that are fully caught up with the leader's log within the allowed lag time. | Apache Kafka Documentation |
| **Join-Semilattice** | Spojový polosvaz | A mathematical partially ordered set where any two elements have a unique least upper bound (join $\sqcup$), satisfying commutativity, associativity, and idempotence. | Davey & Priestley (2002) |
| **Joint Consensus** | Společný (sdílený) konsensus | A two-phase configuration change mechanism in Raft ($C_{\text{old,new}}$) requiring independent majorities from both the old and new configurations, preventing split-brain during cluster rebalancing. | Ongaro & Ousterhout (2014) |
| **Lamport Timestamp** | Lamportovo logické razítko | A scalar integer incremented on local events and updated to $\max(L_{\text{local}}, L_{\text{msg}}) + 1$ upon receiving a message, enforcing $a \to b \implies L(a) < L(b)$. | Lamport (CACM 1978) |
| **Leader Election** | Volba vůdce | A distributed coordination algorithm where nodes designate a single coordinator process to serialize decisions and drive replication. | Garcia-Molina (Bully Algorithm 1982) |
| **Leader Lease** | Pronájem vůdcovství (lease) | A time-bounded grant of authority from replicas to a leader, permitting the leader to serve linearizable read queries locally without consensus rounds as long as the lease remains valid. | Gray & Cheriton (SOSP 1989) |
| **Linearizability** | Linearizovatelnost | A strong consistency model where operations on single objects appear to take effect instantaneously at a discrete linearization point between their invocation and response times, preserving real-time order. | Herlihy & Wing (ACM TOPLAS 1990) |
| **Liveness Property** | Vlastnost živosti | A property stating that "something good eventually happens" (e.g., termination, message delivery); cannot be violated by any finite execution trace. | Alpern & Schneider (1985) |
| **Log End Offset (LEO)** | Konec záznamu v logu | The offset of the next record to be written to a partition replica's local write-ahead log. | Apache Kafka Documentation |
| **Metastable Failure** | Metastabilní selhání | A persistent failure state maintained by self-reinforcing feedback loops (e.g. retry amplification, cache invalidation storms) that persists long after the original triggering fault has resolved. | Bronson et al. (OSDI 2022) |
| **Multi-Paxos** | Multi-Paxos | An optimization of Single-Decree Paxos where a stable leader amortizes Phase 1 across a sequence of log entries, executing consensus in a single round-trip (Phase 2) during steady state. | Lamport (2001) |
| **Network Partition** | Rozdělení sítě (síťová partice) | A failure mode where network communication between two or more subsets of healthy nodes is severed, preventing messages from traversing the boundary. | Standard Networking Taxonomy |
| **NTP (Network Time Protocol)** | Protokol síťového času (NTP) | A networking protocol for synchronizing computer physical clocks over variable-latency packet-switched networks via hierarchical strata. | Mills (RFC 1305 / 5905) |
| **Observed-Removed Set (OR-Set)** | Množina s prioritou přidání (OR-Set) | A CRDT set implementation tagging each added element with a unique tag; concurrent adds and removes resolve with Add-Wins semantics because the add generates a fresh unobserved tag. | Shapiro et al. (2011) |
| **PACELC Theorem** | Věta PACELC | An extension of CAP stating that: If Partition ($P$), choose Availability ($A$) or Consistency ($C$); Else ($E$), choose Latency ($L$) or Consistency ($C$). | Daniel Abadi (2012) |
| **Partially Synchronous Network** | Částečně synchronní síť | A timing model where upper bounds on transmission delay and processing speed exist, but are unknown a priori or only hold after an unknown Global Stabilization Time (GST). | Dwork, Lynch, Stockmeyer (1988) |
| **$\Phi$-Accrual Failure Detector** | $\Phi$-kumulativní detektor selhání | An adaptive failure detector that computes a continuous scale of suspicion $\Phi = -\log_{10}(P_{\text{later}})$ based on historical heartbeat interval distributions, decoupling monitoring from policy. | Hayashibara et al. (SRDS 2004) |
| **Practical Byzantine Fault Tolerance (PBFT)** | Praktická byzantská odolnost proti chybám | The first polynomial-time state machine replication protocol tolerating $f$ Byzantine nodes in asynchronous networks using $3f + 1$ replicas via 3-phase consensus. | Castro & Liskov (OSDI 1999) |
| **Pre-Vote** | Předvolební fáze (Pre-Vote) | An informal inquiry phase in Raft where a disconnected candidate tests if a majority would grant it a vote before incrementing its term, preventing partitioned nodes from disrupting the cluster. | Ongaro (Stanford Thesis 2014) |
| **Quorum** | Kvórum | A subset of cluster nodes whose vote or acknowledgment is sufficient to validate an operation; majority quorums guarantee that any two quorums intersect by at least one node. | Gifford (SOSP 1979), Thomas (1979) |
| **Raft** | Algoritmus Raft | An understandable consensus algorithm designed by Ongaro and Ousterhout that decomposes state machine replication into leader election, log replication, and safety. | Ongaro & Ousterhout (USENIX ATC 2014) |
| **Read-Your-Writes (RYW)** | Čtení vlastních zápisů | A client session guarantee ensuring that if a process writes value $v$, any subsequent read by that same process will observe $v$ (or a later update). | Terry et al. (Bayou, 1994) |
| **ReadIndex** | ReadIndex | A Raft read optimization where the leader records its current commit index, confirms its leadership via heartbeat exchange with a majority, and serves the read once state reaches that index. | Ongaro (2014) |
| **Safety Property** | Vlastnost bezpečnosti | A property asserting that "nothing bad happens"; any violation can be identified in a finite execution trace and cannot be remedied by subsequent events. | Alpern & Schneider (1985) |
| **Saga Pattern** | Vzor sága | An architectural pattern for managing distributed transactions across microservices as a sequence of local transactions coordinated via events, using compensating transactions upon failure. | Garcia-Molina & Salem (1987) |
| **Sequential Consistency** | Sekvenční konzistence | A consistency model requiring that all operations appear to execute in some serial order that is consistent with the program order observed on each individual process. | Lamport (IEEE Trans. Comp. 1979) |
| **Serializability** | Sériovost (serializovatelnost) | The highest isolation level for multi-operation database transactions, guaranteeing that concurrent transactions execute equivalently to some serial, non-interleaved order. | Bernstein, Hadzilacos, Goodman (1987) |
| **Single-Decree Paxos** | Jednodekretový Paxos | The foundational consensus protocol reaching agreement on a single immutable decision using two phases (Prepare/Promise and Accept/Accepted). | Lamport (1998) |
| **Sloppy Quorum** | Volné (nedbalé) kvórum | A leaderless replication configuration where writes are accepted by healthy non-designated nodes when primary nodes are unreachable, relying on Hinted Handoff for eventual sync. | DeCandia et al. (Dynamo, SOSP 2007) |
| **State Machine Replication (SMR)** | Replikace stavového automatu | A technique for building fault-tolerant services by running identical deterministic state machines on multiple servers and feeding them an identical, totally ordered sequence of commands. | Lamport (1978), Schneider (ACM Comp. Surv. 1990) |
| **Strict Serializability (External Consistency)** | Striktní sériovost (externí konzistence) | The combination of Serializability and Linearizability: multi-operation transactions appear to execute in a serial order that strictly respects real-time precedence. | Papadimitriou (1979), Gifford (1981) |
| **Strong Eventual Consistency (SEC)** | Silná koncová konzistence | An eventual consistency model guaranteeing that any two replicas that have received the identical set of updates will immediately be in identical states, without coordination. | Shapiro et al. (2011) |
| **SWIM Protocol** | Protokol SWIM | A scalable weakly-consistent infection-style membership protocol combining localized direct heartbeats with indirect $k$-random peer ping requests for $O(1)$ failure detection. | Das, Gupta, Motivala (DSN 2002) |
| **Synchronous Network** | Synchronní síť | A network timing model where known, strict upper bounds exist on message transmission delay, processing step duration, and physical clock drift. | Lynch (Distributed Algorithms 1996) |
| **Three-Phase Commit (3PC)** | Třífázové potvrzení | A non-blocking atomic commit protocol under synchronous networks and crash-stop failures that adds a `PreCommit` phase to eliminate the blocking coordinator uncertainty window. | Dale Skeen (1981) |
| **Thundering Herd** | Problém dupajícího stáda | A performance degradation scenario where a large number of waiting processes awaken simultaneously to compete for a shared resource or lock, exhausting CPU and network bandwidth. | Systems Performance Taxonomy |
| **TLA+** | TLA+ | A formal specification language based on temporal logic and set theory used to mathematically specify, model check (via TLC), and prove the correctness of concurrent algorithms. | Lamport (Specifying Systems 2002) |
| **Transactional Outbox** | Vzor transakční odchozí pošta | A reliable messaging pattern where database mutations and outgoing event messages are saved atomically within the same local ACID transaction, with a CDC process relaying to the broker. | Richardson (2018) |
| **TrueTime** | TrueTime | Google Spanner's hardware-backed clock API returning a bounded time interval $[t_{\text{earliest}}, t_{\text{latest}}]$ with known maximum uncertainty $\epsilon$, used with commit-wait to guarantee external consistency. | Corbett et al. (OSDI 2012) |
| **Two Generals Problem** | Problém dvou generálů | A thought experiment proving that two nodes cannot reach common knowledge of an agreement across an unreliable, lossy communication link in bounded time. | Jim Gray (1978) |
| **Two-Phase Commit (2PC)** | Dvojfázové potvrzení | A classic atomic commit protocol where a coordinator polls participants in Phase 1 (Prepare) and commands commit/abort in Phase 2, suffering from blocking coordinator crashes. | Gray (1978), Lampson & Sturgis (1976) |
| **Vector Clock** | Vektorové hodiny | An array of logical clocks indexed by process ID; enables distinguishing whether two events are causally related ($a \to b$ or $b \to a$) or concurrent ($a \parallel b$). | Mattern (1988), Fidge (1988) |
| **Wing-Gong (WGL) Algorithm** | Wingové-Gongův algoritmus | A branch-and-bound verification algorithm with memoization for evaluating whether a concurrent execution trace on a shared object satisfies Herlihy-Wing linearizability. | Wing & Gong (1993) |
| **ZooKeeper Atomic Broadcast (ZAB)** | Atomické vysílání ZooKeeperu | A crash-fault-tolerant atomic broadcast protocol designed for primary-backup systems, using 64-bit $zxid$ transaction identifiers composed of a 32-bit epoch and a 32-bit counter. | Junqueira, Reed, Yabandeh (DSN 2011) |
